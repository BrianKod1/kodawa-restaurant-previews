## Purpose

This file studies events as both:

* optional guest participation;
* and an operating condition affecting the overnight stay.

Generator publicly presents an event programme that may include:

* Gen Sessions;
* karaoke;
* beer-pong tournaments;
* festive programming;
* games;
* meetings;
* group gatherings;
* and privately hired spaces.

Generator Copenhagen also promotes several event-capable environments, including:

* Pétanque Bar;
* Chill Out Bar;
* shuffleboard rooms;
* bar and restaurant areas;
* terrace space;
* and PlayBar activity.

The existence of this infrastructure establishes institutional event capability.

It does not establish a current event on a particular date.

```text
Event Capability

≠

Current Event Availability
```

## Event Lifecycle

A guest may encounter an event at several stages.

| Stage            | Required information                                        |
| ---------------- | ----------------------------------------------------------- |
| Discovery        | What kinds of events the institution operates               |
| Booking          | Whether a material event may affect the selected stay       |
| Pre-arrival      | Confirmed dates, times, admission and likely disruption     |
| Arrival          | What is happening during the stay and where                 |
| Event entry      | Eligibility, price, capacity, rules and expected conditions |
| Participation    | Assistance, safety, withdrawal and accessibility            |
| Event completion | Exit, transport, return to room and closing conditions      |
| Post-event       | Complaint, incident, refund or stay-level recovery          |

The event cannot be governed only at its entrance.

## Event Existence and Event State

An event may occupy one of several states:

| State                | Meaning                                        |
| -------------------- | ---------------------------------------------- |
| Announced            | The event has been publicly described          |
| Registration open    | A participation route is available             |
| Scheduled            | Date, time and venue are fixed                 |
| Limited availability | Some capacity remains                          |
| Full                 | No normal capacity remains                     |
| Waitlist             | Entry may become available later               |
| Changed              | A material term has been revised               |
| Delayed              | Start has moved but the event remains active   |
| Cancelled            | The event will not proceed                     |
| In progress          | Entry conditions may differ                    |
| Completed            | Participation has ended                        |
| Archived             | Information remains visible but is not current |

```text
Event Page Exists

≠

Event Is Active
```

The digital system should expose the current state rather than leaving the guest to infer it from publication date or social-media activity.

* and cancellation state.

```text
Published Date

≠

```

## Admission and Entitlement

An accommodation booking does not automatically establish admission to every event.

An event may be:

* included for residents;
* resident only;
* open to the public;
* paid separately;
* invitation only;
* capacity controlled;
* group specific;
* privately hired;
* or age restricted.

```text
Staying at Generator

≠

Admitted to Every Event
```

The system should explain:

1. Who may attend?
2. Is accommodation required?
3. Is advance registration required?
4. Is admission free or paid?
5. Does entry include food, drink or game use?
6. Is identification required?
7. Can a participant leave and return?
8. What happens when capacity is reached?
9. Does the event alter access to an ordinarily shared space?

## Private Hire

Generator Copenhagen actively offers spaces for private meetings and events.

Private hire may produce revenue and expand the institution’s hospitality capability.

```text

Restricted Access
        ↓
```

The system should make clear:

* which space is affected;
* when restriction begins;
* when it ends;

* which services move;
* what alternative remains available;


Where a prominent advertised facility is unavailable because of private hire, an appropriate response may include:

* advance disclosure;
* an alternative space;
* an alternative activity;
* a refund for a separately purchased component;

## Event Failure and Recovery

| Failure                                 | Minimum recovery requirement                                     |
| --------------------------------------- | ---------------------------------------------------------------- |
| Event is cancelled                      | Direct notice where possible and clear refund terms              |
| Event time changes                      | Timely notification and updated authoritative record             |
| Venue changes                           | New route and accessibility information                          |
| Event is full                           | Clear state and waitlist or alternative where available          |
| Registration cannot be found            | Human verification without unnecessary repurchase                |
| Resident cannot reach the room          | Immediate access restoration                                     |
| Private hire removes advertised access  | Advance disclosure and relevant alternative                      |
| Event is inaccessible                   | Equivalent access where possible or honest limitation and remedy |
| Age rule appears only at entry          | Refund or proportionate recovery where prior disclosure failed   |
| Participant wants to leave              | Safe exit without pressure                                       |
| Safety incident occurs                  | Private reporting, immediate support and escalation              |
| Event noise prevents rest               | Stay-level recovery, not only an event apology                   |
| Event photography violates consent      | Removal, escalation and correction                               |
| Paid component is not delivered         | Refund, replacement or equivalent value                          |
| Cancellation remains falsely advertised | Correct all active surfaces                                      |

```text
Event Refund

≠

Complete Stay Recovery
```

If the event materially damages room access, safety or rest, recovery may need to address the accommodation transaction as well.

## Case-Level Research Directions

The following are research directions only.

They are not formal patterns.

### Event-State Legibility

The system should show whether an event is proposed, scheduled, open, full, changed, cancelled, active or archived.

### Event-to-Stay Consequence Mapping

An event should be evaluated by both participant experience and its effect on non-participating residents.

### Private-Hire Displacement Disclosure

When private hire removes ordinary access, the system should disclose the affected resource and the available substitute.

### Optional Event / Non-Optional Consequence

An optional activity may still create unavoidable noise, crowding or access effects.

### Programme Freshness Governance

Time-sensitive event information requires an authoritative and visibly current source.

### Return-to-Stay Integrity

Event completion should include safe withdrawal, room access and restoration of normal stay conditions.

These directions require recurrence and contradiction testing before maturity consideration.
