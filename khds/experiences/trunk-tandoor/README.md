# Purpose

Trunk & Tandoor is the first full production case built deliberately from:

KHDS research

rather than:

pre-research design preference.

This experience exists to answer:

> **What happens when KHDS research is translated into a real hospitality product?**

The goal is not:

to demonstrate every KHDS pattern.

The goal is:

to build the strongest possible Trunk & Tandoor hospitality experience

using only the KHDS knowledge that:

actually fits.

---

# Phase 2 Objective

Phase 1 asked:

> **What hospitality behaviours appear transferable across materially different restaurants?**

Phase 2 asks:

> **Can that research improve a real restaurant experience when design decisions become concrete, constrained, and interconnected?**

This phase moves KHDS from:

Research

↓

Comparison

↓

Governance

into:

Production Translation

↓

Implementation

↓

Production Validation

---

# Why Trunk & Tandoor

Trunk & Tandoor is being used as:

the first full KHDS production case

because:

it already exists as:

a Kodawa Labs concept

and

can now be revisited using:

a substantially stronger research system.

The earlier concept should not be treated as:

the final answer.

It is:

a prior implementation hypothesis.

Phase 2 should determine:

which earlier decisions survive

which need refinement

which should be removed

and

which new decisions emerge from:

the research.

---

# Trunk & Tandoor Is Not Independent Evidence

This distinction remains:

mandatory.

Trunk & Tandoor belongs to:

Track B — Kodawa Labs Validation.

It may test:

- implementation

- user journey

- technical feasibility
- pattern interaction

It must not be counted as:

independent hospitality research.

10 restaurants.

# Phase 2 Research Relationship

KHDS research should:

inform production.

It should not:

dictate production mechanically.

The relationship is:

Research Evidence

↓

Relevant Interpretation

↓

Experience Fit

↓

Production Decision

↓

Implementation

↓

Validation

The missing step is:

Experience Fit.

A research pattern may be:

strong

and still:

not belong in:

Trunk & Tandoor.

---

# Core Production Rule

> **Do not force KHDS into the restaurant. Use KHDS to understand what the restaurant needs.**

This is the governing rule for:

the entire production case.

---

# Pattern Selection Rule

Trunk & Tandoor should not attempt to:

use all:

18 Emerging patterns

9 Candidate patterns

or

every architecture variable.

Each finding should be evaluated through:

1. Is this relevant to Trunk & Tandoor?
2. What guest problem would it solve?
3. What business problem would it solve?
4. What evidence supports applying it here?
5. What would happen if we did not use it?
6. Does another pattern already solve the same problem?
7. Could applying it create unnecessary complexity?

Possible outcomes:

- Apply
- Apply With Adaptation
- Monitor
- Not Relevant
- Contradicted by Experience
- Not Yet Testable

---

# Production Is Another Form of Validation

Phase 1 validated research through:

independent comparison.

Phase 2 introduces:

production pressure.

Production may reveal that:

- a pattern is difficult to implement
- two patterns conflict
- a pattern creates unnecessary complexity
- architecture is missing a variable
- an apparently useful pattern does not improve the actual experience
- a pattern works only under specific conditions
- an implementation pattern is useful even though it is not yet research-derived

These outcomes should be:

recorded

not hidden.

---

# Production Validation Rule

Implementation success does not:

promote research maturity.

A pattern working well in:

Trunk & Tandoor

does not make it:

Validated.

Track B may support:

implementation confidence.

It does not replace:

Track A independent evidence.
